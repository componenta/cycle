# Componenta Cycle

Интеграция Componenta Framework с Cycle ORM/DBAL во время выполнения. Пакет даёт базовые репозитории, инструменты чтения списков и карточек, интерфейсы фильтрации запросов, typecast-классы и фабрики для настройки Cycle.

Обнаружение сущностей, консольные команды схемы и сборка кеша находятся в `componenta/cycle-app`. Если библиотеке нужна только работа с базой во время выполнения, она должна зависеть от `componenta/cycle`, а не от app-пакета.

## Установка

```bash
composer require componenta/cycle
```

Устанавливайте `componenta/cycle-app` только в приложение, которому нужны обнаружение сущностей, консольные команды схемы или интеграция с кешем фреймворка.

Пакет поддерживает Config 3 совместно с DI 5 и Config 4 совместно с DI 6 при наличии совместимых транзитивных зависимостей. PHP 8.4 поддерживается с DI 5; минимальная версия PHP для DI 6 определяется требованиями этого пакета.

## Связанные пакеты

| Пакет | Зачем нужен здесь |
|---|---|
| `cycle/orm` и `cycle/database` | Основной ORM/DBAL слой. `componenta/cycle` добавляет удобные базовые классы и интеграцию, но не заменяет Cycle. |
| `componenta/di` | Нужен для регистрации репозиториев, фабрик и typecast-сервисов в контейнере. |
| `componenta/cqrs` | Часто использует репозитории в command handlers и `DataFetcher` в query handlers. |
| `componenta/paginator` | Используется read-side выборками, когда нужно вернуть slice данных и информацию о навигации. |
| `componenta/cycle-app` | Сканирует классы, строит ORM-конфигурацию и подключает консольные команды. |

## Репозитории

`Repository` расширяет репозитории Cycle ORM и даёт репозиториям приложения единую базу. Используйте репозитории для сохранения агрегатов и поиска по идентификатору.

Доменные переходы должны оставаться в агрегатах и обработчиках команд. Репозиторий не должен превращаться в сервис прав доступа или workflow-сервис.

## Чтение списков и карточек

`DataFetcher` помогает строить read-side выборки на Cycle DBAL: списки, карточки, таблицы админки и API-ответы.

Он умеет:

- определять имя таблицы с возможностью переопределения;
- выбирать колонки по интерфейсам запроса;
- применять пагинацию и опциональный точный total count;
- применять сортировку;
- маппить поля из `snake_case` в `camelCase`;
- преобразовывать значения через кастеры;
- вызывать методы вида `map{FieldName}`;
- батчем загружать связи belongs-to, has-many и many-to-many.

Методы fetcher превращают строки базы в массивы или projection objects. Связи загружаются батчем после сбора строк, поэтому выборки могут избегать N+1 запросов.

## Интерфейсы запросов

Read query object включает нужное поведение через маленькие интерфейсы:

| Интерфейс | Что включает |
|---|---|
| `PaginableInterface` | `limit` и `offset` пагинацию. |
| `RequiresTotalCountInterface` | Возвращает точное общее количество в пагинаторе. |
| `SortableInterface` | Сортировку. |
| `SelectableInterface` | Явный набор колонок. |
| `SearchableInterface` | Поиск через фильтр, заданный fetcher-классом. |
| `DateRangeInterface` | Фильтрацию по интервалу дат. |
| `ListQueryInterface` | Общий интерфейс-маркер для объектов запроса списка. |

`RequiresTotalCountInterface` определяет, возвращает ли пагинатор общее количество. Без него `totalCount` равен null, а `hasNextPage` по-прежнему точно указывает на наличие следующей страницы.

## Точки расширения fetcher-класса

Прикладные fetcher-классы обычно наследуют `DataFetcher` и настраивают его через protected-свойства и методы:

| API | Назначение |
|---|---|
| `$excluded` | Поля, которые нужно удалить из результата после преобразования. |
| `$autoMapToCamelCase` | Автоматически преобразует ключи результата из `snake_case` в `camelCase`. |
| `$fieldMapping` | Явное соответствие поле БД -> поле результата. |
| `$casters` | Соответствие поле -> caster, которое резолвится через `CasterProviderInterface`. |
| `map{FieldName}()` | Метод маппинга для отдельного поля, вызывается после caster-преобразования. |
| `loadRelations()` | Необязательная точка расширения для батчевой загрузки belongs-to, has-many и many-to-many связей. |

Стандартные фильтры: `PaginationFilter`, `OrderFilter`, `SearchFilter`, `DateRangeFilter`, `DateTimeFilter`, `ComparisonFilter`, `BetweenFilter`, `InFilter`, `NotInFilter`, `NullFilter`, `NotNullFilter`, `BooleanFilter` и `SoftDeleteFilter`.

## Typecasts и фабрики

Пакет включает typecast-классы и фабрики для настройки Cycle ORM. Их можно связать вручную или через `Componenta\Cycle\ConfigProvider` в DI-конфигурации.

Встроенные typecast-классы: `UuidTypecast`, `EnumTypecast` и `CarbonTypecast`.

`ConfigProvider` регистрирует фабрики Cycle DBAL/ORM для конфигурации БД, менеджера БД, ORM, схемы, менеджера сущностей, миграций и стандартной core factory. Основные ключи конфигурации находятся в `ConfigKey`.

Если приложение использует автоматическое обнаружение сущностей и кеш ORM-конфигурации, эта часть подключается через `componenta/cycle-app`.

## Производительность

`DataFetcher` кеширует имена методов маппинга на уровне экземпляра и читает текущий выбор связей из запроса. Запрошенное общее количество вычисляется агрегатом над выборкой без пагинации. Без общего количества ограниченный запрос проверяет наличие одного результата после страницы: обычная выборка использует EXISTS, а DISTINCT, группировки и операции над множествами сохраняют своё количество результирующих строк в ограниченном запросе подсчёта. MySQL и SQL Server перед подсчётом через подзапрос определяют количество выходных столбцов и назначают уникальные алиасы, включая случаи `*` и повторяющихся имён. Запрос страницы выбирает только запрошенные строки. Поля страницы передаются в преобразование без изменений. Fetcher закрывает свои statement до загрузки связей, в том числе при ошибке чтения или преобразования строки.

Стандартная конфигурация базы использует обычный SQL-компилятор. Кеш компиляции запросов отключён: во внешней зависимости он может нарушать привязку параметров составных запросов.

Тесты пагинации по умолчанию используют SQLite в памяти. Для проверки тех же публичных контрактов на другой поддерживаемой СУБД задайте `CYCLE_TEST_DB_DRIVER`, `CYCLE_TEST_DB_NAME` и необходимые `CYCLE_TEST_DB_HOST`, `CYCLE_TEST_DB_PORT`, `CYCLE_TEST_DB_USER`, `CYCLE_TEST_DB_PASSWORD` или `CYCLE_TEST_DB_SCHEMA`, затем запустите `tests/DataFetcherPaginationTest.php`. Тесты выбирают строки из литералов, не создавая и не изменяя таблицы.

`tests/DataFetcherCursorTest.php` использует те же переменные подключения MySQL для проверки небуферизованного чтения, кеша запросов, загрузки связей и восстановления после исключений преобразования строк. Без настроенного тестового подключения MySQL этот набор пропускается.

## Границы

`componenta/cycle` содержит поведение работы с базой во время выполнения. Сканирование файловой системы, обнаружение атрибутов, консольные команды схемы и интеграция компиляции принадлежат `componenta/cycle-app`.

Обработчики преобразования типов приложения подключаются явно: `ConfigKey::ROOT => [ConfigKey::TYPECAST_HANDLERS => [CustomTypecast::class]]`. Стандартная цепочка включает UUID, Carbon, перечисления и штатный обработчик Cycle. Если проект использовал неявное подключение классов `App\\Cycle\\Typecast`, зарегистрируйте их в конфигурации приложения. Обработчики с изменяемыми правилами должны создаваться отдельно для каждой роли.

### Динамический выбор полей и сортировка

Если имена полей поступают из запроса пользователя, переопределите `selectableColumns()` и `sortableColumns()`: они возвращают отображение разрешённых публичных имён на доверенные имена колонок БД. Явное отображение полей также определяет выборку по умолчанию; `null` сохраняет прежнее поведение для доверенных запросов. Стандартные фильтры принимают только простые имена колонок или имена с указанием таблицы. Доверенные SQL-выражения задавайте через построитель запросов или собственные фильтры. Авторизация строк и изоляция арендаторов остаются ответственностью вызывающего кода. Не передавайте недоверенные имена без списка разрешённых полей.

UUID хранятся в двоичном формате; стандартная фабрика ORM передаёт значения PostgreSQL `bytea` и двоичные значения SQL Server как LOB-параметры и восстанавливает двоичные строки, шестнадцатеричное представление `bytea` и потоки PDO. При ручном создании `UuidTypecast` сохраняется прежний двоичный результат, если не передать `binaryLob: true`.

По умолчанию сертификаты SQL Server проверяются. Для локального тестового сервера с самоподписанным сертификатом можно явно задать `DB_TRUST_SERVER_CERTIFICATE=true`; не используйте это значение по умолчанию в рабочей среде. Тесты пагинации SQL Server принимают соответствующую тестовую переменную `CYCLE_TEST_DB_TRUST_SERVER_CERTIFICATE`.

### Внутреннее устройство DataFetcher и совместимость

`DataFetcher` оркестрирует чтение проекций. Преобразование строк, управление временем жизни SQL-курсора, пагинация, допуск полей и пакетная загрузка связей выделены во внутренние реализации. Защищённые методы расширения (в том числе `fetchRow`, `transformData`, `mapField`, `fetchResults`, `countRows`, `getColumns`, `getFilters` и методы пакетной загрузки) сохраняют прежние сигнатуры и возможности переопределения. Внутренние классы не являются точками расширения. Обычный путь пагинации не хранит контекст выполнения; изолированный временный контекст сохраняется только для переопределений `fetchResults`, материализующих строки перед передачей в базовую реализацию.

Ключи связей сравниваются средствами СУБД с учётом правил сопоставления строк и преобразования типов. Различные исходные ключи сохраняют отдельные группы результатов, даже если СУБД считает их эквивалентными. В одном пакете не более 500 ключей; размер уменьшается, если проекция содержит дополнительные связываемые параметры. Простые проекции, включая псевдонимы столбцов, используют индексируемое соединение с `VALUES` в SQLite, типизированные массивы или поиск по точным ключам в PostgreSQL, а также поиск по проверенным точным ключам или таблицам порядковых номеров в MySQL и SQL Server. Для подходящих двоичных ключей SQL Server может использовать `OPENJSON`. Если требуется исходное сравнение, для простых проекций MySQL используется единственное обращение к таблице с отдельными параметризованными предикатами. Сложные доверенные проекции используют ограниченные составные запросы. Если MySQL сообщает об ошибке 1137 при повторном обращении к временной таблице, загрузчик выполняет независимые части запроса отдельно до вызова преобразователей связей; в этом исключительном случае возможен один запрос на уникальный ключ. Остальные ошибки передаются вызывающему коду без изменений. Ограничение СУБД на повторное обращение к одной временной таблице внутри одного самостоятельного запроса сохраняется. Метаданные типов и правил сопоставления проверяются при выполнении запроса и не кешируются между вызовами.

Календарные фильтры поддерживают `DATE`, `YEAR`, `MONTH` и `DAY` в SQLite, MySQL, PostgreSQL и SQL Server. Для числовых частей даты используйте числовой формат PHP, например `Y`, `m` или `j`. `DateFilter` проверяет даты ISO, для диапазона использует исключающую верхнюю границу следующего дня, а пустой список отдельных дат не выбирает ни одной строки. Извлечение части даты следует семантике даты и времени СУБД; функции над колонками могут требовать индексов по выражениям.

`SearchFilter` применяет функцию `LOWER` СУБД и к колонкам, и к связанному параметру поиска. Преобразование регистра зависит от СУБД и правил сравнения (встроенная функция `LOWER` SQLite обрабатывает только ASCII). Символы шаблонов `LIKE` (`%`, `_`) сохраняют смысл SQL, включая режим `LikeMode::Exact`. Если требуются полноценное преобразование регистра Unicode или буквальный поиск таких символов, используйте специализированную поисковую реализацию приложения.

Если дополнительному обработчику нужны сервисы DI Componenta или текущая роль ORM, включите его класс также в `ConfigKey::BINDINGS`. Настроенная фабрика получает контейнер и контекст (`database`, `schema`, `role`) и должна создавать отдельный обработчик для каждой роли. Приложение может заменить фабрику, зарегистрированную под `UuidTypecast::class`, совместимой реализацией обработчика Cycle без наследования от стандартного final-класса.

В SQLite границы диапазона `DateFilter` представлены датами ISO без времени. Это позволяет сравнивать как даты, так и одинаково форматированные даты со временем без применения функции к индексируемой колонке. Фабрика ленивых объектов поддерживает извлечение фактически существующих динамических свойств `stdClass` и классов, явно разрешающих динамические свойства. Ссылки динамических отношений разрешаются перед присваиванием: отсутствующее динамическое свойство нельзя пометить ленивым. Поведение обычных объявленных свойств и неразрешённых объявленных отношений сохраняется.

Для условий ORM-запросов по двоичным колонкам UUID используйте `uncast()` маппера соответствующей роли, поскольку запросы Cycle принимают значения в формате базы данных. В командах сохранения сущностей преобразование UUID выполняется автоматически.

Если СУБД возвращает двоичные ключи обычными строками PHP (например, SQL Server), переопределите `DataFetcher::isBinaryRelationKey(string $column): bool` так, чтобы метод возвращал `true` для соответствующих колонок исходной строки. Это включает обработку ключей без потери двоичных данных. Обычный параметризованный путь использует `PDO::PARAM_LOB`; специализированные пути могут передавать байты в связанном массиве или параметре JSON без изменения их значения. Перематываемые потоки `bytea` PostgreSQL определяются автоматически. Не помечайте текстовые и числовые ключи двоичными. В SQLite тип связывания должен соответствовать представлению сохранённого значения (текст или BLOB).

```php
protected function isBinaryRelationKey(string $column): bool
{
    return in_array($column, ['id', 'owner_id'], true);
}
```

## Запуск тестов

Установите зависимости разработки командой `composer install`, затем выполните `composer test`. Тесты используют Pest 4, а при необходимости — строгие утверждения и тестовые двойники PHPUnit. Для запуска отдельных сценариев используйте `composer test -- --filter 'pagination'`. Интеграционные тесты по умолчанию используют SQLite; в CI также проверяются MySQL, PostgreSQL, SQL Server и минимальные совместимые версии зависимостей. Конфигурация тестов считает ошибками предупреждения, рискованные тесты и предупреждения об устаревании.
